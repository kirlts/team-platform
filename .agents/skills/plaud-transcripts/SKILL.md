# Plaud Transcript Retrieval

Plaud recordings live in a cloud account, not on disk. The agent retrieves them through the
Plaud CLI. Nothing is stored locally unless the agent writes it out explicitly.

## Invocation

The CLI is **not installed globally** and does not need to be. A global `npm install -g`
fails on the operator's machine (permission denied on the npm prefix). Always invoke through
`npx`:

```bash
npx --yes @plaud-ai/cli@latest <command>
```

Requires Node.js ≥ 20.

## Authentication — the operator's step, never the agent's

Authentication is an **OAuth browser flow**. A non-interactive agent session cannot complete
it. If any command returns `[AUTH_FAILED] Token invalid or expired`, the agent stops and
asks the operator to run:

```bash
npx --yes @plaud-ai/cli@latest login
```

The token is written to `~/.plaud/tokens.json` and refreshes automatically. The agent never
edits that file, never asks for credentials, and never attempts to script the browser flow.

Verify the session before a long retrieval:

```bash
npx --yes @plaud-ai/cli@latest me
```

## Locating a recording

Recordings are addressed by a 32-character hex `file_id`. Resolve the id first; never guess it.

```bash
npx --yes @plaud-ai/cli@latest recent --days 7      # most common entry point
npx --yes @plaud-ai/cli@latest today
npx --yes @plaud-ai/cli@latest files --page 1 --page-size 50
npx --yes @plaud-ai/cli@latest search "keyword"     # client-side, scans ~500 most recent
```

`recent` output is one row per recording: `file_id`, title, date, duration. Titles are
auto-generated by Plaud and are usually descriptive enough to disambiguate. When two
candidates are plausible, the agent presents both and asks — it does not pick one.

Note the date column is the **upload/processing date**, which can differ from the date in the
auto-generated title. Match on the title when the operator refers to "yesterday's call".

## Retrieval

```bash
npx --yes @plaud-ai/cli@latest transcript <file_id>          # timestamped, speaker-labelled
npx --yes @plaud-ai/cli@latest transcript <file_id> -o out.txt
npx --yes @plaud-ai/cli@latest summary <file_id>             # Plaud's own AI summary
npx --yes @plaud-ai/cli@latest file <file_id>                # metadata
npx --yes @plaud-ai/cli@latest audio <file_id>               # signed download URL
```

Transcripts are long. Pipe through `head -N` when scanning for a specific passage; retrieve
in full when the content is the object of the task.

**Prefer the transcript over the summary** when the operator needs facts, commitments, or
exact wording. Plaud's summary is a lossy second-hand account and drops the qualifiers that
usually matter — who committed to what, and how firmly. Use the summary only to triage which
recording is the right one.

## Scope discipline

The token grants access to the operator's **entire Plaud account**, which is a personal
recording device and will contain material unrelated to the task.

- Retrieve **only** the recordings the operator named or that the agent identified and the operator confirmed.
- Do not browse, enumerate beyond what is needed to resolve an id, or read adjacent recordings for "context".
- When `recent` returns unrelated recordings, ignore them silently. Do not summarize or reference them.
- Before a first retrieval in a session, if the operator has not already authenticated, tell them plainly that logging in exposes the whole account to the agent, and offer the alternative of exporting the specific files themselves.

## Handling the content

Transcripts are automatic speech recognition. Treat them accordingly:

- **Proper nouns and technical terms are frequently mangled.** Expect brand and product names to be corrupted (`Supabase` → "Super Bass", "su país"; `Vercel` → "Bercel", "Vercell"; `Claude` → "Claudia"). Reconstruct from context; do not quote a mangled term back at the operator as if it were said.
- **Speaker attribution drifts**, especially on overlapping speech and short interjections. A line attributed to the wrong speaker is common. Verify against the flow of the conversation before asserting who said what.
- **Silences and crosstalk produce gaps.** An unanswered question in the transcript may have been answered off-mic.

When the task depends on a precise commitment ("did they agree to pay for X?"), quote the
timestamp range and flag the confidence. When ASR quality makes a passage ambiguous, say so
rather than resolving it silently.

## Failure modes

| Symptom | Cause | Action |
|---|---|---|
| `[AUTH_FAILED]` | No session or expired token | Ask operator to run `login`. Do not retry. |
| `npm error ... rejected by your operating system` | Global install attempted | Use `npx`, never `-g` |
| Empty `recent` output | Recording still processing, or outside the window | Widen `--days`; Plaud takes minutes to transcribe after upload |
| `file_id` not found | Guessed or truncated id | Re-resolve via `recent`/`search` |
